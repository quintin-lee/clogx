# core/log.c 文件内整理设计

> 日期: 2026-10-11 · 分支策略: feature branch · 约束: 零行为变化

## §1 目标、范围、非目标

**目标**：`core/log.c`（1765 行）文件内按主题重排分组，每组有统一的分区分隔注释；
函数归位到所属分区；顺手修命名/注释/重复等不改变语义的小问题。

**范围**：只动 `core/log.c` 一个文件，不新增文件，不动构建系统，不动任何头文件。

**非目标**：不拆文件；不改任何函数签名；不改公共 ABI；不做性能优化；
不动测试文件（测试全绿是验收标准，不是修改对象）。

**硬约束**：零行为变化 —— `make test` 全绿 + `make check`（format/tidy）干净；
任何一行语义存疑的"小修"宁可不做。

## §2 分区方案（8 个分区，纯搬运 + 分隔注释）

按现有函数实际分布（行号为设计时实测），重排为以下顺序，
分区间用统一风格的 `/* ===== ... ===== */` 分隔注释：

| 分区 | 内容 | 现状行号 |
|---|---|---|
| 0. 文件头 + 全局状态 | 现有头文档不动；`g_default_logger`、mutex、TLS 变量、span 栈集中到此 | 1–82 |
| 1. 写路径核心 | `logger_writevprintf_internal`、KV 写路径及配套 static helper | 约 340–628 |
| 2. 单例生命周期 | `log_init/destroy/flush/reload`、`logger_init_internal`、stats | 约 277–340、629–664、1351–1590 |
| 3. 多实例 API | 全部 `logger_*` 公开函数 | 1591–1740 |
| 4. Sink 管理 | `log_add/remove_sink`、`logger_add/remove_sink` | 195–276、1656–1667 |
| 5. Trace/Span（合并） | span helper（83–193）+ trace context（721–830）+ export/join/hex（1125–1286）三处合并为一处 | 83–193、721–830、1125–1286 |
| 6. 脱敏 | printf 脱敏 + KV 脱敏链 + `clog_redact_*` API | 826–1124 |
| 7. MDC + Module | thread context + module get/set | 205–235、665–720 |
| 8. 平台适配垫底 | fork 处理 + `clog_mutex_*` 包装（保持文件末尾） | 1287–1350、1741–1765 |

最大的一处搬运是分区 5：span 相关代码现在散在文件头、中、后三处，
合并后 trace 主题第一次完整。

## §3 小修清单（顺手、零语义）+ 验证回滚

**允许的小修**（每条必须同时满足：不改语义、不改签名、diff 一眼可判）：

1. 分区内重复的注释措辞统一（如多处 "fail-open" 表述）。
2. 明显过时/错位的注释修正（如搬运后指向旧位置的注释）。
3. 命名仅限局部变量歧义处，且只改单函数内、零外部引用。

**明确不做**：static 函数改名（涉及交叉引用，review 成本高）；任何逻辑重排；
补新注释描述"为什么"（只修错，不添文）。

**验证**：`make test` 全绿（行为无变化的唯一验收）+ `make check` 干净 +
公共 ABI 符号数不变（`nm -D` 对照）。

**回滚**：单文件改动，整单一个 commit；有问题直接 revert 该 commit。
