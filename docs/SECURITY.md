# Security Policy for clogx

## Reporting Vulnerabilities

If you discover a security vulnerability in clogx, please report it **privately** to the maintainer:

- Email: [quintin <2449164582@qq.com>](mailto:2449164582@qq.com)

Do not submit public issues or pull requests for suspected security vulnerabilities until the issue has been addressed. Private disclosure allows us to investigate, develop, and test a fix before public release.

## Response Timeline

We acknowledge security reports within **48 hours** of receipt. For confirmed vulnerabilities, we aim to:

- Provide an initial response within 48 hours.
- Develop and test a patch within 7 days (for confirmed critical/high severity issues).
- Release a fixed version (patch/minor as appropriate) coordinated with the reporter's preferred timeline.

We will credit contributors in the release notes and/or a follow-up CVE announcement, unless anonymity is requested.

## Supported Versions

| Version | Status | Reason |
|---------|--------|--------|
| Latest stable (pre-1.x) | Supported | Active development |
| Previous minor versions | Supported for critical security fixes | As maintainers have capacity |

Note: clogx is currently pre-1.0; APIs may change between minor releases. Backward compatibility is not guaranteed until 1.0.

## Disclosure Policy

Public disclosure of security details will occur only after a fix is available in a released version. We do not encourage public disclosure before a patch is ready, as this could expose users to risk.

## PGP Encryption (Optional)

For encrypted security reports, the maintainer can provide a PGP key upon request via email. Contact us directly if you prefer to encrypt your vulnerability report.
